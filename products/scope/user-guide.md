# 用户手册

## 工作区与面板

在 Activity Rail 或组件管理中找到组件，加载后打开工作区。中央显示组件业务内容；Context 负责当前操作，Inspector 显示对象属性或测量，Output 显示趋势、结果与消息。宿主保存面板的显隐、停靠和工作区布局。画布中的移动、缩放、隐藏或专注只影响当前组件中央区域。

关闭工作区前，先结束设备连接、采集或后台任务。宿主会要求组件执行停止流程；若仍有活动工作区或资源未释放，组件可能拒绝卸载。

## 组件管理

1. 在组件管理中导入 `.sscomponent`、包含组件的目录或自包含 ZIP。
2. 核对名称、版本、描述和来源，再加载组件。
3. 打开工作区；切换版本前关闭同 ID 的活动工作区并卸载当前版本。
4. 移除组件时确认没有正在运行的工作区。

插件是同进程原生代码，具备与宿主相同的系统权限。仅安装可信来源的组件。组件 ID 相同、版本不同的安装项可以并列保存，但同一时间只能运行其中一个版本。

## Serial Scope

在 Context 中扫描并选择端口、波特率及解析引擎。**Delimited numeric** 处理按行发送的逗号分隔数值，如 `1.2,3.4,5.6`；**Raw text** 用于查看文本。波形与通道视图反映收到的数据；终端发出的内容取决于所选行结束方式。断开后再改变会影响协议状态的设置。一个串口在 Scope 内由 Core 租约独占；如果端口已被占用，先关闭占用它的工作区或外部程序。

## TN160 Thermal 与 TN160 USB NCM

选择与实际设备传输方式相符的组件。连接后先确认身份、固件和实时画面，再查看 Center 5×5、NTC、ADU、FPS 与趋势。UF2、标定和 Flash 写入属于设备流程：按组件界面给出的状态、前置条件和结果执行，保留设备输出与导出记录。串口版使用共享 `SerialTransport`，USB NCM 版使用对应网络链路。若设备身份、固件或状态不匹配，应停止该流程并检查连接。

## T256/T384/T640 USB NCM

设备网络就绪后连接，先检查身份、profile、RAW16 画面和 Y16，再判断是否存在有效温度模型。实验两点流程采用低温与高温黑体采样并核验设备回读；其结果只说明实验模型写入及验证状态。不要把它用作独立温度精度证书。设备响应不确定时不要重复写入。

## Y-Serein HMI

创建或打开离线工程，管理页面、控件、属性、绑定和事件，再在本机预览并生成目标包。预览与目标包生成不会自动证明串口通信或硬件下载成功；这些步骤需要目标后端和设备端配合。

## YSerein Swarm Simulator

选择目标协议和网络参数，创建网格编队或导入舞步，查看模拟状态与三维预览。播放来源、启动、暂停、停止和清除操作以当前界面状态为准。扩容时逐级核对主站在线数、控制成功数、网络与电脑负载，不只看模拟器生成数。

## YSerein Universe

选择实际工程根目录，检查 GMAT、适配器和 OpenSpace 的可用路径，再运行轨道生成、格式转换和可视化流程。外部工具的安装、授权、输入文件和运行错误由相应工具与工程配置决定。

## 数据与设置

便携部署时，组件默认位于程序旁的 `Components/`；运行数据根目录是程序旁的 `runtime/`。其中 `runtime/config/` 放配置，组件可使用 `runtime/plugins/` 保存自己的运行数据。不要把这些目录当作自动备份或自动日志导出：标定证据、截图、CSV 或目标包应按对应组件界面显示的路径核对。
